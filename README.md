# yinian-plugin-couchdb

一念（Yinian）**多端同步**的传输后端：把一念加密后的字节搬到你自己的 CouchDB。

- 插件 id：`yinian-couchdb`（仓库名带 `plugin-`，manifest id 不带——与其他一念插件一致）
- 扩展点：`replica`（一念 `docs/11-plugin-architecture.md` §5.4）
- 时效：**轮询**（当前版本 `capabilities.watch = false`，见下面「实时同步」）
- 需要：一台你能访问的 CouchDB 3.x

> **从 0.1.0 升级要重装。** 0.2.0 把 manifest id 从 `yinian-plugin-couchdb` 改成
> `yinian-couchdb`（对齐其他插件的命名）。宿主按 id 认插件，所以它不是「升级」而是
> 「换了一个插件」：先卸载旧的、装新的、重填连接配置，再去「设置 → 多端同步」把配置
> 指向新后端。**远端数据不受影响**，加密口令也还在系统钥匙串里。

## 它做什么，不做什么

**只搬字节。** 一念在本机做完加密（XChaCha20-Poly1305）再交给它，它看不懂内容——
你的 CouchDB 管理员、中间的反向代理、备份磁盘上看到的都是密文。所有冲突判定、
字段级合并、删除语义都在一念核心，这个插件里**一个业务判断都没有**。

**不用 CouchDB 的复制协议**，也不引 PouchDB。一念只把 CouchDB 当「带范围查询的对象
存储」用：绑死复制协议的话，将来的 WebDAV 后端就得再写一套收敛逻辑，而
「换后端不动核心」当场作废。

**不产生 revision 冲突。** 变更日志分片是 immutable append-only 文档，写进去就不再
修改，所以永远撞不到 CouchDB 的文档级冲突模型。也正因如此，重复写同一个 key 时的
409 直接当成功（契约要求 `put` 幂等，而网络重试会真的发生）。

## 配置

装好之后在一念的「设置 → 插件」里填：

| 字段 | 说明 |
|---|---|
| CouchDB 地址 | 带协议与端口的根地址，**不要带数据库名**。建议 https |
| 数据库名 | 不存在时自动创建。CouchDB 要求小写字母开头 |
| 用户名 / 密码 | 需要该库的读写权限。CouchDB 3 默认不允许匿名写入 |
| 请求超时 | 默认 30 秒，上限 60（宿主对 put/get 的超时就是 60 秒） |

填完点「测试连接」。然后到「设置 → 多端同步」选这个后端、输**加密口令**并启用。

**加密口令不在这个插件里。** 它存在本机系统钥匙串，永不同步、永不上传；插件拿不到它，
也拿不到明文。每台设备输一次同一个口令，两台才能互相解密。

### 为什么权限是 `net: "*"`

CouchDB 是**你自建的**，地址只有你知道，插件作者没法预先列出白名单。所以只能声明
通配，安装界面会为此高亮告警——那个告警是对的，请自己确认填进去的地址可信。

### http 还是 https

同步内容本身已经端到端加密，http 也不会泄露任务标题。但 **Basic Auth 的账号密码在
http 下是明文过链路**，所以除非只在局域网里用，都该上 https。

## 实时同步

一念的 `replica` 契约支持 `watch`（CouchDB 的 `_changes?feed=longpoll`，亚秒级），
本版本**还没实现**，`capabilities.watch = false`，一念会退回低频轮询兜底。

订阅只是加速、不是唯一通道：不实现 watch 只是慢一点，不会漏数据。实现它需要宿主侧
配套的 `replica.changed` / `replica.heartbeat` 通知路由与心跳判活，两边一起做才能验证。

## 远端长什么样

一个对象 = 一个文档，`_id` 就是一念给的对象键：

```text
meta.json                                   初始化标记（明文，只存加密 salt，salt 不是秘密）
journals/{deviceId}/{seq}.pack              各设备的变更日志分片（密文）
```

文档里只有两个字段：`b`（base64 密文）与 `s`（解码后字节数，供列举时报大小）。
键由一念生成、不含业务语义，插件不改写它——改了换设备后就对不上。

## 开发

```bash
npm install
npm run verify   # build + doctor + 测试
npm run pack     # 打出可安装的 zip
```

测试跑在一个**进程内 mock CouchDB** 上（`tests/mockCouch.mjs`），不需要真实实例；它只
实现被用到的端点，但保证 409 语义、`_all_docs` 范围查、删除要带 `_rev` 这些行为与真实
CouchDB 一致——这几处恰恰是错了以后「同步看起来在跑但数据对不上」的地方。

真机验证仍然要做一次：mock 保证不了 CouchDB 的排序规则、代理行为与权限模型。
